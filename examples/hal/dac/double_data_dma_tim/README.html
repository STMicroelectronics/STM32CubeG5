Example: hal_dac_double_data_dma_tim

Example version: 2.0.0

How to use the DAC HAL API to generate a signal using the DMA double mode feature with a timer trigger. This feature allows the MCU to decrease data transfer bandwidth by transferring two data blocks with a single DMA request, every two TIM trigger.

1. Detailed scenario

Initialization phase: At main program start, the mx_system_init() function is called. It initializes the peripherals, nonvolatile memory (such as flash memory, NVM, or external memories), MPU regions (if applicable), the system clock, and the SysTick.

The application executes the following example steps:

Step 1: The DAC, the DMA, and the TIM are initialized. The double data mode of the DAC enables the transfer of two data blocks at each DMA request, one out of two triggers.

Step 2: Converts the data from millivolts to raw format because the DAC cannot directly handle millivolts format but only raw format between 0 and the maximum DAC resolution.

Step 3: The DAC conversion is started using the DMA feature and the TIM is started to trigger the DAC conversion. Every two TIM triggers, the DAC generates a DMA request to get two data blocks, one for the current trigger and the other the following one.

End of example: The DAC conversion is repeated endlessly. Due to the DMA circular mode, every two TIM trigger, the DAC generates a DMA request to get two new values to convert. The example status is reported via the variable ExecStatus, and the status led remains turned on in case of success.

The final output signal is a sine with a frequency of 1kHz, an amplitude of VDDA / 2 and an offset of VDDA / 4.

2. Example configuration

DAC: The DAC uses the DMA double data mode feature to transfer data to be converted. So, the peripheral is configured with specific parameters:

  • Timer trigger.
  • 12-bit DAC data is used with right-alignment.
  • Output buffer enabled.
  • Circular buffer.
  • Double data mode: 2 data blocks are transferred every other trigger (one out of two).

DMA: Configured to transfer, on DAC request, two data from the memory to the DAC registers. Data is stored as a buffer and the address of the element to be transferred is incremented after each transfer.

Note: Data transferred to the DMA are in raw format to be used by the DAC. The macro LL_DAC_CALC_VOLTAGE_TO_DATA converts data in voltage units to raw format.

TIM: Configured to trigger the DAC with the following parameters:

  • Timer update event is used as an output trigger (TRGO).
  • Parameters have been chosen to get a SIG_FREQ = 1kHz signal in the output of the DAC.
  • The repetition counter (if present) is not used here.
The aim is to have a 1kHz sine waveform.

The buffer that contains the sine waveform samples is BUFFER_SIZE_HALWORD long (60 samples). Therefore, each sample of the buffer signal should be converted with a frequency of: TRGO_freq = Sig_freq * BUFFER_SIZE = 60kHz

Note: This frequency corresponds to the timer frequency.

To get this 60kHz, the period is configured according to the formula below: TRGO_freq = Timer_clock_freq / ((PRESCALER_VALUE + 1) * (PERIOD_VALUE + 1))

Note: The “+1” used in the formulas is needed because the registers’ values start from 0.

To get the better precision, the frequency is defined with a low PRESCALER_VALUE while the PERIOD_VALUE does not overflow the ARR register (16 bits / 32 bits).

PERIOD_VALUE = (Timer_clock_freq / (TRGO_freq * (PRESCALER_VALUE + 1))) - 1

3. Hardware environment and setup

3.1. Generic Setup

This section describes the hardware setup principles that apply to any board.

On STM32G5 series.

Clock configuration for the timer counter:

The AHB clock (HCLK) and system core clock are set to the system clock (SYSCLK), since prescalers are set to 1.

The timer input clock (Timer_clock_freq) is set to its respective APB clock (PCLK), since APB prescalers are set to 1.

Timer_clock_freq = PCLK = HCLK = SYSCLK (system clock) so Timer_clock_freq = HCLK in Hz

Usual clock diagram of STM32G5xx MCUs’ peripherals:

The HCLK is set to 280MHz.

PERIOD_VALUE calculation with APB prescaler set to 1 and HCLK set to 280MHz: > PERIOD_VALUE = (Timer_clock_freq / (TRGO_freq * (PRESCALER_VALUE + 1))) - 1

This equation can be resolved with: > PRESCALER_VALUE = 0 > > PERIOD_VALUE = (280 MHz / 60kHz) - 1 > PERIOD_VALUE = 4666 (rounded to the nearest integer)

4. Troubleshooting

Using the buffer feature of the DAC can impact its accuracy. To have further information about the DAC accuracy, you can check the datasheet and the reference manual corresponding to your MCU.
