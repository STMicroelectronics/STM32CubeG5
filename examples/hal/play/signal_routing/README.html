Example: hal_play_signal_routing

Example version: 2.0.0

How to configure the PLAY peripheral to act as signal router. This example shows how to use the HAL drivers to configure the PLAY peripheral to perform a signal router from a TIM internal signal to an external GPIO.

1. Detailed scenario

Initialization phase: At main program start, the mx_system_init() function is called. It initializes the peripherals, nonvolatile memory (such as flash memory, NVM, or external memories), MPU regions (if applicable), the system clock, and the SysTick.

The application executes the following example steps:

Step 1: Configures, initializes, and starts the PLAY & TIM peripherals.

Step 2: Toggles the TIM TRGO internal signal each second. The signal is routed to the PLAYi_INx input signal, which is output on the PLAYi_OUTy signal. Returns to step 2 indefinitely if no error occurs.

End of example: The example run indefinitely or until an error occurs.

You can verify that the example runs properly via the status LED and the ExecStatus variable.

If you enable USE_TRACE, you can follow these execution steps in the terminal logs:

[INFO] Step 1: Initialization and configuration of the PLAY & TIM peripherals COMPLETED.
[INFO] Step 2: TIM TRGO toggled.
[INFO] Step 2: TIM TRGO toggled.
...

2. Example configuration

The PLAY peripheral is configured to route the TIM TRGO internal signal to the PLAYi_OUTx output pin. The PLAYi_INx input signal is used to trigger the routing. One lookup table (LUT) is used to route the TIM TRGO signal to the PLAYi_OUTx output. The PLAYi_OUTx output signal is connected to an external GPIO pin.
