Example: hal_tamp_active_detect

Example version: 2.0.0

How to automatically erase the backup register when tamper event occurs, using the TAMP HAL APIs.

1. Detailed scenario

Initialization phase: At main program start, the mx_system_init() function is called. It initializes the peripherals, nonvolatile memory (such as flash memory, NVM, or external memories), MPU regions (if applicable), the system clock, and the SysTick.

The application executes the following example steps:

Step 1: initializes the peripheral and configures the active tamper (TAMP_OUT/TAMP_IN).

  • The backup domain write protection is disabled in tamper init to access to the backup registers.
  • Connect externally the TAMP_INx to TAMP_OUTx pins with a wire.

Step 2: sets the backup register to the value 0xAAAAAAAA and checks the written data.

Step 3: starts the tamper and enables the interruption so that the TAMP continuously compares the pseudorandom output signal with the monitored input.

  • Remove the connection of the (TAMP_OUT/TAMP_IN) pins.

Step 4: waits for the tamper detection interrupt. It is generated when signal mismatch on the active tamper pair.

Step 5: checks that the hardware automatically clears the backup register on tamper detection.

Step 6: stops the tamper input and deinitializes the peripheral.

End of example: After step 6, the example is completed. You can verify that the example runs properly via the status LED and the ExecStatus variable.

If you enable USE_TRACE, you can follow these execution steps in the terminal logs:

[INFO] Step 1: Device initialization COMPLETED.
[INFO] Step 2: Backup register 0 WRITTEN.
[INFO] Step 3: Tamper STARTED. Disconnect the pins to generate a tamper detection....
[INFO] Step 4: Signal mismatch. Tamper event DETECTED.
[INFO] Step 5: Backup register 0 CLEARED.
[INFO] Step 6: de-init
...

2. Example configuration

This example demonstrates the following peripherals:

TAMP:

The tamper is configured in interrupt mode.

  • “active tamper” means a continuous comparison between a random signal from a tamper output and the signal input from a tamper input.

The TAMP kernel clock source is the LSI oscillator.

RCC:

The backup domain write protection is disabled to access to the TAMP domain and backup registers.

4. Troubleshooting

Here are the points of attention for this specific example:

Tamper kernel clock: The TAMP kernel clock is usually the LSI although it is possible to select other clock sources in the RCC. Refer to the RCC chapter in the Reference Manual of your STM32 device for more details.

Backup domain Power: The TAMP features and backup registers are part of the backup domain that remains powered-on by VBAT when the VDD power is switched off.

Reset behavior: The backup registers are not reset by system reset. After reset, the backup domains are protected against possible unwanted write accesses. So, you must enable access to the TAMP domain and TAMP registers to configure the TAMP.
