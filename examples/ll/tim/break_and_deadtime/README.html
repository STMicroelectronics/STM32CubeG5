Example: ll_tim_break_and_deadtime

Example version: 2.0.6

How to configure the TIM peripheral to generate two complementary PWM (Pulse Width Modulation) signals with symmetric deadtime insertion.

1. Detailed scenario

This scenario demonstrates how to configure the TIM peripheral to generate two complementary PWM (Pulse Width Modulation) signals with symmetric deadtime insertion. Deadtime is a short period inserted between the switching of the high and low signals to prevent short circuits and reduce switching losses in power electronics.

Initialization phase: At main program start, the mx_system_init() function is called. It initializes the peripherals, nonvolatile memory (such as flash memory, NVM, or external memories), MPU regions (if applicable), the system clock, and the SysTick.

The application executes the following example steps:

Step 1: Initializes the timer peripheral with deadtime insertion feature.

Step 2: Starts the timer peripheral to generate a PWM with deadtime insertion.

End of example: If no error occurs, the PWM signal is generated indefinitely.

You can verify that the example runs properly via the status LED and the ExecStatus variable.

2. Example configuration

2.1. Timer configuration

The goal is to use TIM peripheral to generate a symmetric PWM signal with deadtime insertion on channel 1X and its complementary channel 1XN.

The TIM is configured as follows:

  • The timer is configured as a PWM generator in up-counting mode.
  • The timer is configured with symmetrical deadtime.
  • The deadtime value is set to 3.7 microseconds.
  • The timer prescaler is configured to set the timer counter clock to 64 kHz.
  • The PWM duty cycle is initially configured at 50% for both channels. However, the real duty cycle is lower due to deadtime insertion, resulting in an actual duty cycle of 47%.
  • The PWM frequency is configured at 8 kHz.

To obtain 8kHz as PWM frequency, the ARR value is chosen as indicated below:

PWM period = tim_cnt_ck period * (ARR + 1)
PWM frequency = tim_cnt_ck frequency / (ARR + 1)
ARR = (tim_cnt_ck frequency / PWM frequency) - 1
ARR = (64 kHz / 8 kHz) - 1
ARR = 7

The PWM duty cycle, expressed as a percentage, is calculated as the ratio of the output active state to the PWM period, multiplied by 100:

duty_cycle_percent = (CCR / (ARR + 1)) * 100
CCR = (duty_cyle_percent * (ARR + 1)) / 100
CCR = (50 * (7 + 1)) / 100
CCR = 4

To obtain a duty cycle of 47% after accounting for deadtime:

PWM period = 1 / PWM frequency
PWM period = 1 / 8 kHz = 125 us
Initial_pulse_duration = 50% of 125 us
Effective pulse duration = Initial_pulse_duration - deadtime value
Effective_pulse_duration = 62.5 us - 3.7 us = 58.8 us.
Actual_duty_cycle = ( Effective_pulse_duration / Period ) * 100.
Actual_duty_cycle = ( 58.8 us / 125 us ) * 100
Actual_duty_cycle = 47 %

In this example, the timer is configured with symmetrical deadtime. The deadtime value is 3.7us. This configuration is applied to the PWM signal on channel 1X and its complementary channel 1XN.

The deadtime value configured correspond to DTG (Dead time generator) bitfield of TIMx_BDTR register. This value, which is not a time unit, can be computed as below.

The system clock configuration is specific to each STM32 MCU (see section Hardware environment and setup).

2.2. GPIO configuration

Two pins must be configured, one for each PWM signal: see the specific boards setups

The GPIO pins are configured in:

  • Alternate function as a timer channel of the same timer instance
  • Push-pull mode with no pull-up or pull-down resistors activated.

3.2. Specific board setups

On STM32G5 series.
Common configuration.

Timer’s counter clock configuration with prescalers set to 1:

  • The timer’s internal input clock (tim_ker_ck) is set to the system clock (SYSCLK).

    tim_ker_ck = SYSCLK (system clock)

    To obtain the timer’s counter clock frequency (tim_cnt_ck), the timer prescaler register (TIM_PSC) is computed as follows:

    TIM_PSC = (SYSCLK / tim_cnt_ck ) - 1

In this configuration:

  • The SYSCLK is set to 280MHz.
  • The HPRE prescaler is set to 1.
  • The timer counter clock is set to 64kHz.

To obtain a timer counter clock at 64kHz with the HPRE prescaler set to 1 and the SYSCLK set to 280MHz, the timer prescaler must be:

timer_prescaler = (280 MHz / 64 kHz) - 1 = 4374 (integer rounded down)

For this example, with a deadtime value of 3.7 microseconds, the encoded value 0xE0 is obtained as follows:

DTG[7:5]=0b0xx -> DT= DTG[7:0] x tdtg with tdtg=tDTS. DTG[7:5]=0b10x -> DT= (64+DTG[5:0]) x tdtg with Tdtg=2xtDTS. DTG[7:5]=0b110 -> DT= (32+DTG[4:0]) x tdtg with Tdtg=8xtDTS. DTG[7:5]=0b111 -> DT= (32+DTG[4:0]) x tdtg with Tdtg=16xtDTS.

  • tDTS (timer Dead Time Sampling) Calculation:

    tTIM_KER_CK = 2/280 MHz (since timer clock division is set to 2)
tDTS = 1 * tTIM_KER_CK = 7.14 ns

  • DTG[7:5] Calculation:

For this example:

DTG[7:5]=0b0xx -> 0ns <= DT <= 907ns (127 * 7.14ns) DTG[7:5]=0b10x -> 914ns <= DT <= 1814ns ((64 + 63) * 2 * 7.14ns) DTG[7:5]=0b110 -> 1827ns <= DT <= 3599ns ((32 + 31) * 8 * 7.14ns) DTG[7:5]=0b111 -> 3656ns <= DT <= 7197ns ((32 + 31) * 16 * 7.14ns)

To achieve a deadtime of 3.7us, we need to use DTG[7:5]=111

  • tDTG (timer Dead Time Generator) Calculation:

    DTG[7:5] = 0b111 (which is 7 in decimal)
tDTG = 16 * tDTS = 114 ns

  • DTG[4:0] Calculation:

    - DT = (32 + DTG[4:0]) * tDTG
- DTG[4:0] = ( 3.7 / tDTG ) - 32
- DTG[4:0] = 0.45 = 0 (integer rounded down)

Finally, DTG[4:0] = 0b00000 and DTG[7:5] = 0b111, resulting in DTG[7:0] = 0b11100000, which is equivalent to 0xE0 in hexadecimal.

Therefore, a deadtime value of 3.7 microseconds gives the encoded value 0xE0.

4. Troubleshooting

Here are the points of attention for this specific example:

System clock: The timer clock depends on the system clock configuration. Changing the CPU clock or the peripheral bus’ clock affects the PWM frequency.
