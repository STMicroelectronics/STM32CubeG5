# __Example: *ll_posenc_endat3*__

**Example version:** 2.0.0

[![User Manual](doc/read_the-UM.svg)](https://dev.st.com/stm32cube-docs/examples/arch-v1/en/index.html "An offline version is also available in the STM32Cube firmware package.")

How to configure and use the POSENC peripheral with the LL API to communicate with an EnDat3 encoder. The example configures the POSENC EnDat3 protocol, uses a timer trigger to synchronize communication, requests foreground position data, and reads the encoder turn and angular position.


## __1. Detailed scenario__

__Initialization phase__: At main program start, the `mx_system_init()` function is called. It initializes the peripherals, nonvolatile memory (such as flash memory, NVM, or external memories), MPU regions (if applicable), the system clock, and the SysTick.

The application executes the following __example steps__:

__Step 1__: The application initializes the POSENC and timer instances generated by STM32CubeMX.

__Step 2__: The application configures the EnDat3 clock division factor and enables the EnDat3 interrupt used to notify that new foreground data is available.

__Step 3__: The application starts the timer used as the POSENC strobe trigger for EnDat3 communication synchronization.

__Step 4__: The application sends the EnDat3 HELLO command, then prepares a foreground DATA0 request to receive encoder data.

__Step 5__: The application waits for the POSENC interrupt callback to report new data, then reads the cycle-based memory and updates the `encoder_turn` and `encoder_position_millidegree` variables.
            Returns to step 5 indefinitely if no error occurs.

__End of example__: This is an endless example. If an error occurs, the application exits the execution loop and enters the error handler.

You can verify that the example runs properly via the status LED and the `ExecStatus` variable. When initialization succeeds, the status LED remains on. If an error occurs, the status LED flashes with a short on time and a long off time.

If you enable `USE_TRACE`, you can follow the execution status in the terminal logs.


## __2. Example configuration__

[![Configuration Manual](doc/configure_with-ConfigurationMa.svg)](https://dev.st.com/stm32cube-docs/examples/arch-v1/en/configure/config_toc.html "An offline version is also available in the STM32Cube firmware package.")

### __2.1. IPs configuration__

__POSENC__:

The POSENC peripheral is configured to communicate with an EnDat3 encoder:

  - POSENC instance: `POSENC1`
  - protocol: EnDat3
  - initialization layer: LL
  - strobe resynchronization: enabled
  - trigger source: `TIM1_TRGO` connected to POSENC strobe 0
  - interrupt: enabled for foreground data availability

The POSENC clock source is `PLL1P`. The example configures the EnDat3 clock division in the applicative code before starting foreground requests.

__TIM__:

The timer is configured as the POSENC synchronization trigger source:

  - timer instance: `TIM1`
  - initialization layer: LL
  - trigger output source: update event

TIM1 starts before the EnDat3 HELLO command is sent, so the POSENC peripheral receives the synchronization trigger required by the communication sequence.


## __3. Hardware environment and setup__

### __3.1. Generic Setup__

This section describes the hardware setup principles that apply to any board.

Connect an EnDat3 encoder to the POSENC signals of the STM32 board. The POSENC output signal drives the encoder receive input, the POSENC input signal receives encoder data, and the POSENC enable signal controls the transmission direction.

## __4. Troubleshooting__

[![Troubleshooting](doc/debug_with-Troubleshooting.svg)](https://dev.st.com/stm32cube-docs/examples/arch-v1/en/debug/debug_toc.html "An offline version is also available in the STM32Cube firmware package.")

Find below the points of attention for this specific example.

__Encoder connection__: Check that the EnDat3 encoder signals are connected to the expected POSENC pins and that the encoder is powered before starting the example.

__No new data received__: If the `new_data_received` variable remains cleared, check the POSENC interrupt configuration, the TIM1 trigger output, and the EnDat3 signal wiring.

__Invalid position value__: If `position_degree` or `turn` does not update as expected, check that the connected encoder supports the foreground DATA0 request used by the example and that the EnDat3 communication clock is suitable for the setup.
