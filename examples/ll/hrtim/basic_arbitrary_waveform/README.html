Example: ll_hrtim_basic_arbitrary_waveform

Example version: 2.0.0

How to configure the HRTIM peripheral in continuous mode to generate two basic non-PWM waveforms with multiple set/reset/toggle requests. The waveforms generated by the HRTIM output channels can be displayed using an oscilloscope.

1. Detailed scenario

This scenario demonstrates how to configure a HRTIM to generate two basic non-PWM waveforms.

Initialization phase: At main program start, the mx_system_init() function is called. It initializes the peripherals, nonvolatile memory (such as flash memory, NVM, or external memories), MPU regions (if applicable), the system clock, and the SysTick.

The application executes the following example steps:

Step 1: Initializes the input clock, counter clock, and output clock of the HRTIM timer. Configures the output channels and the GPIO pins. Starts the periodic DLL calibration.

Step 2: Starts the timer non-PWM waveform generation on each HRTIM output.

End of example: If no error occurs, both waveforms are generated indefinitely.

2. Example configuration

2.1. Timer configuration

The HRTIM is configured as follows:

  • When available, the delay-locked loop (DLL) must be calibrated before high resolution can be used.

  • The HRTIM timer is configured in continuous (free-running) and up counting modes.

  • The HRTIM timer prescaler aand period are configured to generate signals at 100 kHz.

  • For the HRTIM output channels, the output active level is HIGH. The set/reset sources of the crossbar are configured in a way to generate two different non-PWM waveforms:

    • First channel: toggle on TIMx period (TIMx_PERIOD), toggle on TIMx compare unit1 (TIMx_CMP1), toggle on TIMx compare unit2 (TIMx_CMP2).
    • Second channel: set on TIMx_PERIOD and TIMx_CMP2, reset on TIMx_CMP1 and TIMx_CMP3.
    • TIMx_CMP1 = TIMx_PERIOD / 4;
    • TIMx_CMP2 = 3 * TIMx_PERIOD / 8;
    • TIMx_CMP3 = TIMx_PERIOD / 2;

Note that the HRTIM timer configuration depends on the HRTIM peripheral input clock, which is derived from the system clock tree. So, it is required to define the system clock configuration and to determine the HRTIM timer input clock before defining the HRTIM timer and output channel configuration.

The system clock configuration is specific to each STM32 MCU (see section Hardware environment and setup).

2.2. GPIO configuration

Two pins must be configured for each waveform signal: see the specific boards setups

Each GPIO pin is configured in:

  • Alternate function as a HRTIM output channel of its respective timer instance.
  • Push-pull mode with no pull-up or pull-down resistors activated.

3. Hardware environment and setup

3.1. Generic Setup

Each signal generated by the timer channel can be displayed by connecting an oscilloscope to the corresponding board connector.

3.2. Specific board setups

On STM32G5 series.
Common configuration.

To provide the high resolution, the HRTIM must be fed directly by the PLL high-frequency output.

It is recommended to have the periodic calibration enabled for the DLL, with the lowest calibration period.

Each timer in the HRTIM has its own individual clock prescaler, which is used to adjust the timer high-resolution clock fHRCK.

In this configuration:

  • sys_clk set to 250MHz.
  • fHRTIM: set to 250MHz (HRTPRE = 1).
  • fHRCK: set to 4GHz (prescaler = 16).

With a 250 MHz input clock, the period is set to 100 kHz as indicated below: PER = fHRCK / fPWM = 4GHz / 100 kHz = 40000

  • TIMx_CMP1 = TIMx_PERIOD / 4 = 10000;
  • TIMx_CMP2 = 3 * TIMx_PERIOD / 8 = 15000;
  • TIMx_CMP3 = TIMx_PERIOD / 2 =20000;

Two arbitrary waveforms are generated on HRTIM1_CHE1 and HRTIM1_CHE2 outputs, with the following conditions:

  • HRTIM1_CHE1: toggle on TIME period, toggle on TIME compare unit1, toggle on TIME compare unit2.
  • HRTIM1_CHE2: set on TIME_PERIOD and TIME_CMP2, reset on TIME_CMP1 and TIME_CMP3.
On board NUCLEO-G564RE.

The selected timer is TIME with TIME_CHE1 and TIME_CHE2 selected as outputs.

4. Troubleshooting

Here are the points of attention for this specific example:

System clock:

  • To provide the high resolution, the HRTIM must be fed directly by the PLL high-frequency output.
  • The HRTIM clock depends on the system clock configuration. Changing the CPU clock or the peripheral bus’ clock affects the generated signal frequency.

GPIO slew rate:

The GPIO slew rate is an important parameter that affects the performance of high-frequency signals. Refer to the AN4899 application note in case of issues.

Timeout management: Polling flag instructions can cause the example to enter an infinite loop. To prevent this, a timeout mechanism is implemented. When the timeout is reached, the program exits the loop and reports the error at the application level. This mechanism is controlled by the USE_LL_APP_TIMEOUT compilation flag, which is disabled by default to reduce code footprint. If the example execution appears to be stuck in an infinite loop, enable this mechanism for debugging by setting USE_LL_APP_TIMEOUT to 1 in ll_example.h.
